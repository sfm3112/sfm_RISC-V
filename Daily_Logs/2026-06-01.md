## Multiplexer
* After some research on systemVerilog syntax limitations, learned you can make a variable number of inputs with a variable width by using the syntax: [numberOfInputs][InputWidth]inputName
* Also need the multiplexer logic to be variable, could be achieved with an if check to ensure select is within the select number
* systemVerilog version of always @(*) is always_comb
	- always_comb is for always blocks but only logic based, no memory or clocks

## Arithmetic Logic Unit
* The functions of the ALU are determined by the values in Func3 in the instruction word
* Although not represented in the datapath schematic, the ALU also needs to recieve the second most significant bit from the Func7 category for a few operations
* Add and sub functionality can be achieved using the same hardware, where the rsB signal is XORed with the second MSB of Func7 to achieve subtract functionality
* systemVerilog has built in operators for differentiating shifting logically and arithmatically (>> vs >>>)
* It is also important to remember the difference between defining a variable and casting a value:
	- When using a universal bitwidth (WIDTH), defining a variable must use the following format: [WIDTH-1:0]
	- Unlike defining a variable, zero is not counted, so the following format is used: WIDTH'

## Register
* registers are inherently memory modules, therefore the always block should not use always_comb, rather it should use always_ff
* The D-flip flop also cannot be constructed using the same syntax tools as with combinational logic modules
	- DFF needs non-blocking assignments (<=) as opposed to blocking assignments (=)
	- DFF does not need to use "assign" as this is not a continuous assignments
