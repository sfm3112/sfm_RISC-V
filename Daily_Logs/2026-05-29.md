## Refocusing and redefining approach
The old approach of filling out the connections between the DP and CU first is suboptimal.

**The new approach will be as follows:**
1. Create shell components within DP with no wiring yet
2. starting at individual components (ALU, registers, logic blocks, etc.) define necessary wires, working backward to higher level files
3. fill out internal HDL starting with individual components
4. Fill out the CU after DP is completed
 
## Complications
Since the registers are all the same, copied 32 times, it seems sensible to generate them using a generate for loop
* **Complicaton:** The signals coming out need to be multiplexed. 32 registers with 32-bits of data will be rather long to describe, but there do not seem to be any short cuts like a generate for loop
In writing the instantiation of the memory module, it is noted the addresses can only be 12 bits, whereas the PC and MAR signals were originally intended to be 32-bits
* For the PC signal, the 20 MSBs can most likely be discarded for the current project
* For the MAR signal, the 20 MSBs will memory map to IOPs
* Could also simplify the integration of communication protocols like UART or I2C, which would otherwise need to be implemented using software (difficult)
