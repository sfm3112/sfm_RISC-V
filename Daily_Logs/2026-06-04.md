## Control Unit Architecture
The control unit will be broken up into machine cycles, very closely mapping to the control state table from the design phase.
* The way the control unit differentiates between instructions is with the OpCode
* To make the control unit easier to understand, the different OpCodes will be labelled
	- In VHDL this can be achieved using the "constant" keyword
	- SystemVerilog uses the analogous keyword "localparam logic"

## The necessity of MC1
As per the current (6/4/26) iteration of the ASM chart, MC1 is intended to give the program time for the CU to decode the IW.
* This is absolutely necessary when there is delay between the instruction word being fetched and arriving at the control unit
* Since the program memory is local RAM, there should be virtually no delay between the instruction word being fetched and decoded
* A slight deviation from the ASM chart will be attempted which will neglect the "CU decodes IW" machine cycle
* **EXPLANATION:** In the academic RISC processing unit, the IW evaluation was inside the sequential block, it couldn't look at IW until the clock edge after IW was updated
	- The new design puts the combinational logic outside the sequential block, allowing the IW to be decoded between rising edges, but before the next cycle begins
