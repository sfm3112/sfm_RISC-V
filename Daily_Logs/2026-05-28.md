## Issues detected while filling out the CST
The CST comprises of all signals controlled by the control unit. It indicates which control signals activate during which machine cycles
* Explored the possibility of making the MAX select multiplexer signal based on the opCode
	- After looking at the relevant opCodes, the MAX_sel signal could be wired directly to IW[6], reducing necessary complexity in the control unit
* Concluded pipelining is not really necessary for the current project
	- The current architecture utilizes bits within the instruction word itself to control various multiplexers within the datapath. This makes pipelining the current design virtually impossible, and would require significant fundamental redesign of the datapath, increasing the complexity and risk of data hazards significantly
* CST Correction (P:R/W Signal): 
	- Caught a major logical discrepancy in the initial MC0 (Instruction Fetch) row where P:R/W was set to 1 (Write). 
	- Because the Program Memory side of the execution is strictly read-only, corrected this control line to a permanent 0. 
	- The Program Memory port will never perform a write operation; any future live code loading will occur via the shared data port instead.

## Memory Subsystem (PM/DM Block)
* Originally the memory was combined to facilitate a highly efficient pipelined design
* The pipelined design was gradually abandoned as more of the datapath was planned out
* Enough of the signals depend on the current instruction word bits to where pipelining would require substantial fundamental redesign of the datapath
* It has been decided that reverting to an exclusively Harvard or Von Neumann architecture would not provide enough benefit over the current memory architecture to make the conversion necessary
