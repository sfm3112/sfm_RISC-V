## 2D Arrays
The RISC-V architecture calls for 32 registers each 32-bit. This results in a 2D array of wires which need to be multiplexed by row.
* SystemVerilog does support a form of 2D Array notation
* The wire declaration uses the following format: logic [ROW][COLUMN]wireName;
* To pass just a row into a module instantiation where the bitwidth is implied uses the following notation: wireName[i] 
* There is no clear way to use just a column with just one line and requires extracting each element in the column individually

## The Immediate Multiplexer
* Originally the plan was to use the instruction word for the select of the multiplexer
* After further analyzing the instruction word and recognizing a minimum of 4-bits would be needed to differentiate the five types
* It has been determined this is too inefficient to use the n-bit multiplexer file
* In its place, a simple case statement will be used

## RTL Viewer Analysis
Inspecting the RTL viewer gives insight on how Quartus iterprets the design
* The decoder is instantiated as a RAM block
	- Theoretically works, but not the most efficient resource utilization
	- Not ideal
* The Immediate Processor block is correctly modelled with just vectors and no logic blocks
	- The Immediate processor is only supposed to reorder the vector so this is correctly
* The registers are correctly modelled as an array of D flip flops
* The proceeding multiplexers appear to be correct
	- Cannot tell if it outputs by row or column until a test bench is created
* ALU block appears correct, nothing abnormal apparent
* PM/DM correctly utilizes RAM auto generated from Cyclone library
* Program counter correctly uses a DFF array to store the program address with an adder to increment the address upon a program count instruction
* **Observation:** Based on the RTL viewer, most of the design is actually wire routing and not logic gates
