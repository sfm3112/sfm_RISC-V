## BLTU and BGEU
* One idea to do unsigned comparisons would be to look at the carry bit instead of the negative bit
* This would work if the 32-bit number is actually 33-bit, where the MSB of each number is always zero, thus maintaining the unsigned component
* Then the old carry bit is now a sign bit, correctly denoting positive and negative numbers
* Branch less than unsigned will trigger when the carry bit is zero, and Branch greater than or equal to unsigned will trigger if the carry bit is 1

## MC2 AUIPC and JAL

## byteena_b
This signal tells the memory if it should store a byte, half, or word.
* In preparing to implement this signal correctly, a key requirement for official RV32I ISA compatibility was discovered: data must be byte addressable
* In order to implement this requirement, some hardware designs must be altered
	- The program counter must increment by 4, not 1
	- Since the memory block will remain 32 bits wide, the 2 LSBs of PCout are dropped before going to the program address
	- Stores become more tricky, requiring a combinational block between MARout and the memory block: funct3 will tell memory if its writing a word, half, or byte, and the 2 LSBs of MARout will determine where the half and byte go in the word
	- the load combinational block will also need to be similarly altered, as it currently always takes the least significant half and byte from the word
